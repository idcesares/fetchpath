## Delivered in M20

- **`FP-145` (HTTP/2 & adaptive scheduler P0 fixes):**
  - Replaced zero-margin prefix-starvation checks with hysteresis (`PREFIX_SLOW_SHARE = 0.35`, `PREFIX_MIN_AGE = 1500 ms`, `BLOCK_GRACE = 2 s`, `BLOCK_REPLACE_COOLDOWN = 3 s`) and time-based asymmetric goodput smoothing (`GOODPUT_WINDOW = 3 s`, `GOODPUT_RISE_TAU_SECS = 0.25`, `GOODPUT_DECAY_TAU_SECS = 1.5`) in `crates/fetchpath-http/src/scheduler.rs`.
  - Scheduled the HTTP/2 independent-socket `PoolPolicy::Trial` right after the `width = 2` baseline and unlocked controller width growth (`Controller::resume_probing`) when independent sockets gain `>= 15%`; aligned `easy.pipewait` with `PoolPolicy`; added `Controller::revert_starved()` when a doubled probe cannot fit within `max_ahead`.
  - Added bounded cooldown re-probing after transient dips (`REPROBE_COOLDOWN_WINDOWS = 24`, `RECOVERY_COOLDOWN_WINDOWS = 12`, capped at `96`) while keeping 429/503 throttle lockout permanent (`crates/fetchpath-http/src/controller.rs`).
  - Raised `TransferLimits::default()` ceiling to `max_concurrency: 8`, `max_active_requests: 16` (`crates/fetchpath-http/src/lib.rs`).
- **`FP-146` (Single-pass pipelined SHA-256 & callback isolation):**
  - Removed synchronous disk read-back and SHA-256 from `PrefixTracker` (now in-memory extent merging only) and moved incremental hashing into the background `CommitQueue` worker thread with a reused 256 KiB read buffer (`crates/fetchpath-core/src/checkpoint.rs`).
  - Added `Store::validate_staging_hasher` (seeding incremental `Sha256` on resume without a second disk read) and `Store::publish_verified` (O(1) staging length check + `PublicationIntent`/`PublicationFence`/hard-link publication) while retaining full disk `validate_staging()` for crash recovery (`crates/fetchpath-storage/src/lib.rs`, `crates/fetchpath-core/src/transfer.rs`).
- **`FP-147` (Extent-bitmap checkpoint format v2 & prefix-choke removal):**
  - Upgraded `fetchpath-storage` checkpoints to Format v2 (`CompletedExtent { start, end, sha256 }` list strictly past `committed_len`, strict invariant validation on `commit`/`decode_record`/`validate_staging_state`, full v1 backward-compatible load + v2 upgrade on commit, and `PublicationIntent` forbidding non-contiguous extents).
  - Upgraded `PrefixTracker`, `CommitQueue`, and `transfer.rs` to cache per-extent SHA-256 digests on the background worker without re-reading already-hashed extents, commit out-of-order extents on periodic 1 s ticks (`>= 64 KiB` slices) and graceful `RetainStaging` pauses (all slices), and fold merged extents into the single-pass file digest.
  - Extended `ResumePoint` with `completed_extents` so `fetchpath-http` builds its `Frontier` strictly over missing gaps (clipping lane 0 at the first retained extent, treating `offset == 0` with extents as a verified resume across `200`/`206`/`416`), and lifted the default run-ahead window from `3 s` to `12 s` (`TransferLimits.max_ahead_seconds`).
- **`FP-148` (Coalesced write buffers, async disk writer & NTFS sparse staging):**
  - Added `LaneCoalescer` (512 KiB per-lane write coalescing with 200 ms slow-link age flush) and `WriteQueue` (8 MiB bounded async disk I/O worker with recycled buffer pool and explicit backpressure propagation that feeds `fetchpath-http`'s `sink_nanos` controller) in `crates/fetchpath-core/src/checkpoint.rs` and `crates/fetchpath-core/src/transfer.rs`.
  - Separated socket-thread overlap tracking (`accepted`) from disk-thread durability tracking (`on_disk`, updated strictly after `write_payload_at` succeeds) so `CommitQueue` never reads unwritten bytes; ensured interrupted backpressure batches are returned to `LaneCoalescer` for `RetainStaging` flush or `RemoveStaging` discard.
  - Added best-effort Windows `FSCTL_SET_SPARSE` (`set_sparse` / `is_sparse` via `windows-sys` `DeviceIoControl`) in `crates/fetchpath-storage/src/lib.rs`, enabled on segmented staging and cleared before final `sync_payload` + publication.
- **`FP-149` (RFC 9110 strong `Last-Modified`, sequential compression & flexible `RequestContext`):**
  - Implemented zero-dependency RFC 9110 §5.6.7 HTTP-date parsing (`parse_http_date`) and §13.1.5 strong validation (`strong_validator`: strong ETag wins; explicit weak ETag never falls back to `Last-Modified`; absent ETag, `Date - Last-Modified >= 1 s` authorizes safe `If-Range` resume and segmentation) in `crates/fetchpath-http/src/lib.rs`, `scheduler.rs`, and `fetchpath-core/src/transfer.rs`.
  - Enabled transparent `Accept-Encoding` decompression (`easy.accept_encoding("")`) on non-ranged sequential transfers while ignoring compressed wire `Content-Length` so decoded bodies are never clipped, and enforcing `Accept-Encoding: identity` whenever byte-range segmentation is active.
  - Extended `fetchpath-http::RequestContext` and `fetchpath-core::RequestContext` with validated `user_agent`, scoped `custom_headers` (rejecting CRLF/NUL and reserved framing/range headers, stripped across cross-origin redirects, included in credential-free/fingerprint accounting), `proxy` URL validation, and redacted `Debug` output.
- **`FP-150` (Global & per-job bandwidth pacing, job priorities & per-host fairness):**
  - Added lock-light hierarchical `TokenBucket` and `BandwidthPacer` (`crates/fetchpath-http/src/pacer.rs`, re-exported via `fetchpath-core`) enforcing `max(global_delay, job_delay)` with atomic live rate updates, Windows timer-jitter hysteresis (`MIN_SLEEP_THRESHOLD = 8 ms`), prompt cancellation, and pacing inside `Engine::drive` outside `multi.perform()` / `sink_nanos` with pacing-adjusted `Claim.activity` / `paced_before_first` tracking so low-rate or live-downshifted multi-lane transfers never trip false stalls.
  - Added additive backward-compatible Protocol v1 fields (`JobPriority`, `EngineSettings.max_bytes_per_second`, `EngineSettings.max_active_per_host`, `PolicyPatch.priority`, `PolicyPatch.max_bytes_per_second`, `JobSnapshot.priority`, `JobSnapshot.max_bytes_per_second`) and regenerated `crates/fetchpath-protocol/schema/protocol-v1.schema.json`.
  - Upgraded `fetchpath-session` (`Session::update_policy`, `Engine::apply`, `reconcile_locked`, `persist.rs`, `durable.rs`, `settings.rs`) with live global/per-job pacing, `High -> Normal -> Low` priority admission, soft per-host fairness + optional hard `max_active_per_host` cap (with RFC 3986 scheme-validated `url_host`), persistence across restarts, `PolicyChanged` revision bumping, and strict principal bounds (agents cannot mutate `EngineSettings`, set `High` priority, or lift/raise existing per-job caps).
- **`FP-151` (Shared engine-wide HTTP connection, DNS & TLS session pool):**
  - Added `(principal, CredentialScope)`-partitioned `ConnectionPool` and `ConnectionPartition` (`crates/fetchpath-http/src/pool.rs`, re-exported via `fetchpath-core`) backed by bounded per-partition checkout pools of idle `curl::multi::Multi` handles (`MAX_IDLE_MULTIS = 8`, `MAX_PARTITIONS = 64` LRU idle eviction). Each checked-out `Multi` exclusively owns its TCP keep-alive/HTTP/2 connection cache, DNS cache, and Windows Schannel/TLS session cache on one thread at a time (avoiding libcurl 8.22's cross-`Multi` `CURLSH` `cpool->locked` and Schannel `multi->admin` refcount races) and returns to the partition in `Engine::drop` only when completely drained, untainted, and not unwinding, with `pipelining(false, true)` restored.
  - Enforced defense-in-depth credential & cross-principal isolation across `fetchpath-session` (`Session::pool_for_record`), `fetchpath-core` (`transfer.rs`), and `fetchpath-http` (`scheduler.rs` sticky initial eligibility + `pool_tainted` discard on redirect `Set-Cookie`/userinfo; `single.rs` unpooled): credentialed jobs (cookies, `CredentialRef`, referer, custom headers, URL userinfo, or proxy) and distinct principals never share connections, DNS entries, or TLS sessions.

## Limits still held

- Sub-second 64 MiB loopback bursts (`unshaped` / `no-etag`) still show ~71–128 ms of engine overhead over raw transfer from final `sync_all`, per-job JSON metadata commit, and CLI/daemon IPC (addressed by `FP-156` SQLite journal).
- Process-kill interruption tests verify `recoverable` durability across process termination, not OS crash or power loss.
- Until `FP-152` lands, HTTP/3 remains unavailable (`http3_unavailable`).
- Until `FP-153` and `FP-154` land, Metalink multi-source downloads remain sequential and FTP/FTPS/SFTP stop at `fetchpath-http`.
