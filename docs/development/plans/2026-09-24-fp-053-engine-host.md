# FP-053: the fetchpath engine

**Goal:** `fetchpath engine` hosts one session behind the authenticated pipe (FP-052), as the only owner of the queue; every client attaches to it or starts it; it exits when nothing is left to do. [Platform design](../../architecture/specs/2026-09-24-engine-platform-design.md) §5.

**Constraints:** One owner of the queue at any time, including against the desktop, which still owns it in-process until FP-055. Recovery completes before any command is accepted. No console window when a client starts the engine. Strong-model review of ownership and recovery ordering.

## Decisions

1. **Data folder.** `FETCHPATH_APP_DATA_DIR` when set (as the browser host already honors), otherwise `%APPDATA%\app.fetchpath.desktop`, the desktop's folder. The engine adds `engine-secret-v1.bin` and `engine-endpoint-v1` beside the session's files.
2. **Single owner.** The engine holds the desktop's `instance.lock` with a deny-sharing handle for its lifetime. A second engine exits at once, and so does the engine while the desktop runs; the desktop, finding the lock held, exits too (until FP-055 makes it a client). Unlike the desktop, the engine fails closed: any error opening the lock stops it, because two owners corrupt the queue.
3. **Startup order.** Lock, then load the session (restart recovery runs here), then one reconcile, then the secret, a fresh pipe name, the pipe, and last the endpoint file. A client can only reach the engine after the endpoint is published, so no command is accepted before recovery.
4. **Serving.** A thread per connection: authenticate, then read commands one at a time and reply. A subscription reply is followed by a forwarding thread that sends events and progress until the stream or the connection ends; that connection's idle limit is turned off. `EngineShutdown` replies, then stops the engine.
5. **Staying alive.** The engine runs while any authenticated client is connected, or while it has work of its own: a job that is queued, scheduled (including an automatic retry) or running. Paused jobs and failures waiting for a person do not keep it running: nothing happens to them until a person acts, which starts a client, which starts the engine, which restores them. With neither for the grace period (60 seconds; `--idle-grace-ms` for tests), it stops. Stopping cancels running work to its checkpoints and saves, as quitting the desktop does.
6. **Launch or attach** (`fetchpath_protocol::launch`). Read the endpoint and secret and connect. If there is no endpoint, no engine behind it, or no secret yet, start `fetchpath engine` detached and windowless (breaking away from the caller's job object where allowed), then retry until connected or 10 seconds pass. Two clients racing to start it start two engines; one wins the lock, the other exits, and both clients connect to the winner.
7. **Version mismatch and restart.** The engine refuses other protocol majors with `contract.unsupported_version` (FP-050). Restarting must work across versions, so it is a transport request: `hello` may carry `intent: "restart"`. It needs the secret like any connection; the engine answers `welcome`, stops as in 5, and the helper then starts the new build's engine.
8. **Sign-in start.** A setting, off by default (`startEngineAtSignIn`, written only when on so a 0.1.0 settings file writes back unchanged). When a person changes it, the engine adds or removes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value `Fetchpath engine`. It never removes the value at startup, so an engine run for tests with another data folder cannot undo a person's choice.
9. **Commands.** `fetchpath engine` runs the host in the foreground; `fetchpath engine status` attaches without starting one and prints its status; `fetchpath engine stop` asks it to stop.

## Tests

Two engines started together (one serves, one exits); an engine killed during a download and relaunched (the download continues from its checkpoint); idle exit after the grace period, and a scheduled job keeping it alive past it; launch or attach from a client with no engine running; a command with another protocol major refused, and a restart request stopping the engine so the next attach starts a new one.
