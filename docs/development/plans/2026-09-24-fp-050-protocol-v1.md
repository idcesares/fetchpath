# FP-050: protocol v1 and the `EngineClient` interface

**Goal:** A `crates/fetchpath-protocol` crate that defines the engine protocol's messages, framing, JSON Schema and client interface, following [the job contract](../../architecture/JOB-CONTRACT.md) and [the platform design](../../architecture/specs/2026-09-24-engine-platform-design.md) §4. No queue logic, no transport.

**Constraints:** Contract field names and codes where they exist. No dependency on the session (the design lists serde and windows-sys only; schemars and uuid are added for the schema and for fresh ids). Additive changes keep the major version, so readers tolerate unknown fields and values. Nothing secret in `Debug` output.

## Shape

| Module | Holds |
|---|---|
| `ids` | UUID newtypes per identifier kind; strict UTC `Timestamp` without a date crate |
| `error` | `ErrorCode` (validated, with the contract's codes as constants), `Action`, `ErrorScope`, `ProtocolError` |
| `model` | `SensitiveUrl`, job states and kinds, `Progress`, `JobSnapshot`, details, queue stats, media inspection, settings, engine status |
| `command` | `CommandEnvelope`, `Command`, `JobRequest`, `JobInput`, destination, policy |
| `message` | `ServerMessage` (`reply`, `event`, `progress`), `Reply`, `CommandResult`, `JobEvent`, `EventPayload`, `ProgressSample` |
| `frame` | Length-prefixed framing with a 4 MiB cap, version-first decoding, `KNOWN_COMMANDS` |
| `schema` | The schema document and its canonical text |
| `client` | `EngineClient`, `EventStream`, `Subscription` |

## Steps

1. Write the types, with an `unknown` fallback on every closed set a newer engine may extend.
2. Decode commands in two steps: read the object, keep the `command_id`, check `schema_version`, check the command type against `KNOWN_COMMANDS`, then parse strictly. So refusals carry the right code and correlation.
3. Tests: one sample of every command, result and event (a `match` makes a new variant without a sample a compile error); round trip through frames; every sample against the exported schema; the checked-in schema matches the generated text (`FETCHPATH_BLESS_SCHEMA=1` rewrites it); version, size, malformed and unknown-command refusals; split-frame reassembly; redaction; forward compatibility; object safety of the client trait.
4. Mutation-check the drift test and each refusal.
5. Workspace checks, regenerate third-party notices, update the contract (§9 codes, §12 example), the repository map and [the engine protocol record](../ENGINE-PROTOCOL.md).
